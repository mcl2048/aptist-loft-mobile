# Demonstrated LOFT release lessons

Read the active repository's build/resource/validation records for current versions and outcomes. These lessons came from task loftmobile-1125-01; they change decisions rather than replace the user's scope.

## Bindings and build inputs

- Rustup selects by working directory, not Cargo --manifest-path. The root environment explicitly pins Rust1.100.0 so root/CI/native commands match the workspace.
- UniFFI0.32 uses global --config and a positional library. Keep explicit crate roots in bindings/uniffi.toml and immutable Kotlin records in the per-crate config. Regenerate native/bindings together; cargo test alone may not update the cdylib.
- gomobile searches PATH for gobind. Locate the module-locked executable with go tool -n gobind; do not run init and install a moving latest tool. API29/with_gvisor and ABI flags must match actual tests.
- Production outputs are ARM64. Software x86_64 tests require paired loftTestAbi/absolute loftNativeGeneratedRoot and separate native/build directories. Host and emulator artifacts must not overwrite the production generated root.
- The linked sing/sing-tun application requires compatible GPL distribution and retained original notices. Independent Rust Apache metadata does not relabel every linked dependency.

## Ownership and receipts

- A zero resource counter may coexist with pending socket/session construction or cleanup. ownership_pending and completion joins prevent false release; a caller timeout cannot dispose the remaining owner.
- A Go duplicate's Close does not prove Android's original TUN closure. Close failures and late callbacks retain unconfirmed ownership; Stop remains retryable/diagnosable.
- Abort/Drain/Stop need one bounded completion owner/waiter, including cancellation during Ready/business open. Closing the stack before lazy-flow closers avoids the observed admitted-SYN mutex deadlock.
- TCP/UDP copy owners return their lease only after both directions finish. Empty UDP is data, not EOF; actual Pro0/65507-byte fragmentation/reassembly and half-close tests exposed bugs that controller-only tests did not.
- Terminal failure effects must be one-shot without suppressing delayed construction settlement or the later first true Blocked receipt. Repeated abort state notifications must not create a callback/publication loop.
- Publish sequence and business generation are different. Reserve/query/encode atomically in one publisher, then reject stale UI binding/request/sequence tuples.
