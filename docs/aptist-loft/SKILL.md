## Decisions that must remain true

- Rust owns business state and new LOFT server logic. Kotlin supplies Compose, private Binder and OS capabilities; Go reuses the protocols/TUN stack. One private `:vpn` owner shares the core and lazy Go runtime. UI appearance, visibility and Fold resizing do not own the VPN.
- Anonymous startup is local. Unavailable identity/mail/Shield adapters must return their real boundary; do not manufacture a connection, empty inbox, verified server or software-safe verdict. A framework release does not complete the P0–P5 roadmap.
- A connection uses a generation-bound service ticket, single-use raw credential delivery, immutable idempotent canonical policy and exact PackageManager-reported installed/shared-UID routing freeze. Current Android11+ launcher visibility cannot prove unreported hidden members or a full-device inventory. Canonical delivery precedes raw consumption. Publish Connected/Blocked/Disconnected only from matching actual authentication/TUN/protection/closure receipts; retiring and pending construction remain owned until joined.
- Stop/revoke bypass ordinary work. Poison projects immutable Unavailable and must stop real forwarding. A late equal-generation Connected frame cannot replace a later Stop/Unavailable capture; reserve the transport sequence before querying Rust. Go can legitimately report Running with pending startup ownership; wait for join without faulting or publishing Ready. Atomically fence late pending callbacks after settled readiness and closure.
- Keep the200-node directory accessible in50-row read-only pages, bound to configuration generation and UI binding/request epochs. Preserve selected metadata across pages without changing Rust's active connection.
- X's fixed-target application UDP is1–1024 bytes; Pro's is0–65,507, including empty packets.66,023 is Pro's envelope ceiling. Ordinary SOCKS5 has no tunnel encryption. Preserve mature half-close and authenticated crypto rather than inventing replacement formats.
- Actual sockets are protected and bound before use. Node bootstrap resolution is distinct from business DNS; failed tunneled DNS never falls back to physical DNS. Gateway DNS/Firewall libraries remain on the node and require their own configured resolver/policy receipts.
- DNS/WebRTC protection belongs before all transport adapters. Freeze the actual service owner/shared-UID scope and independent policy epoch; only matching current-client/TUN facts prove enforcement. Node-domain Fake-IP routes restore original FQDNs, retain stable TTL renewals and pin live/advertised-TTL identities through final reply I/O, including conservative late-write quarantine. Use bounded, passive TTL/lease reclaim so exhaustion recovers; fixed528 KiB is inside the8 MiB total and separate from released dynamic resources. TCP/IP cannot identify arbitrary expired caches forever. Confirmed closed totals may survive Stop, never its proof. Distinguish synthetic from real answers, revoke on loss/Abort/Stop, reject unknown aliases and never resolve business DNS physically. The workspace contract is `docs/contracts/network-privacy.md`; Hydra is separate and Disabled by default.
- Keep complete imported links in the local guest SQLCipher repository and restore them through Rust validation. Test the original service-facing credential delivery after restart, with synthetic SOCKS5/X/Pro inputs. Retain node IDs/order and the monotonic allocator. Treat certificate time checks at new connection admission separately from structural recovery. Snapshots, ordinary saved state and logs contain only permitted redacted metadata. The Binder import path remains bounded by its own envelope.
- Android Keystore wraps a random per-store database key with authenticated provisioning and active phases. Use app-private no-backup storage and force a recovery receipt when an active vault loses its key or database. Keep a single SQLCipher connection and commit before publishing changes. Open on the existing normal control worker and keep Stop independent of the factory and disk locks. Reopen from Android after a transient failure. Permanent loss uses explicit clear-storage/re-import recovery. See `docs/contracts/encrypted-storage.md`.
- LOFT Hub uses a public Pages origin, an internal Rust Worker service binding and D1. Register the exact Pages callback in Portal before configuring Worker secrets. The `hub-install` prepare phase discovers the actual Pages hostname. Portal confidential OAuth keeps clientSecret and the Portal bearer in Hub. The APP has an independent one-use proof, an explicit browser return/complete action and a short Hub-only session. Preserve the exact issuer and Portal source authority, including Support eligibility and the no-machine-scope registration for users across tenants. Read `docs/contracts/hub.md`.
- Hub mail operates on the signed-in user's `mail.read` consent and current source authorization. Keep source read state, 20-row token-bound pages, native safe text, and explicit file saves. Clear the mobile projection on account/profile/expiry changes and fence late receipts. No remote heartbeat maintains a short session. Keep endpoint and runtime evidence alongside actual Android interaction.
- Keep stable native module IDs and entry policies. The persistent module rail uses icons, localized accessibility names and explicit selection semantics. Sensitive screens use capture and obscured-gesture protections. Physical overlay and TalkBack acceptance need device evidence.
- Resource contracts precede background work. Bound queues, flows, bytes, operations and cleanup; apply Android Go scheduling in the handset process, not only the build shell. Retain the Service/protector until actual owned joins, without calling that zero-leak/PSS acceptance. Standard AndroidX initializers remain; prohibit added perpetual wake locks, heartbeats, forced-GC loops or automatic cloud/mail/scanner polls.
- VPN foreground notifications follow actual service/resource receipts, use a native status icon and priority Stop, and remain independent of UI lifetime. Check both notification permission and channel visibility; Android13+ denial can hide the drawer/icon while FGS continues. Mail has an independent inert channel and accepts only Rust-authorized current-scope events. Portal's `notifyUnread` is a database marker, not mobile push; actual event/provider/long-term subscription authority must be delivered before claiming new-mail push. Read the workspace's `docs/decisions/notifications.md` for integration and limits.

## Execution and delivery

Final acceptance artifact is the project-root `bin/loft.apk` (on this server: `/home/coder/LOFT-mobile/bin/loft.apk`). Each delivery must place the actual final signed ARM64 Release APK there, verify that exact file's version, package/ABI, ZIP/ELF alignment, signature and secret scan, and record its SHA256 plus matching source/build/test receipts. State the signing identity and actually executed Android/device scope accurately. Replace this canonical file atomically only after final verification. Task completion is assessed against this artifact and its evidence.

Gateway `/home/coder/Loft-Gateway` and Portal `/home/coder/aptist-portal` are read-only inputs, pinned in the mobile source records. Mobile changes belong in the owned repository. Use generated UniFFI and module-locked gomobile/gobind with `with_gvisor`; verify matching native inputs and16KiB alignment. Follow explicit file ownership and coordinate heavy builds on this server.

Private task files can contain a GitHub PAT and private nodes. Read them through the bounded redactor; never print their contents or use token-bearing URLs/arguments. Scan real Git-index blobs and archive members before a user-authorized push; preserve remote history and confirm the exact pushed SHA. Scope any external action to the user's actual authorization.

Use real validation/receipt/packet/cancellation tests where behavior matters. Keep original failure and red/green receipts, then run the complete affected suites. Bind every result to its actual source and consumed native/APK inputs; an old checkpoint retains its old hashes and scope. Wire tests reuse APP boundaries; preserve APP and standalone foundation counts separately. Separate host, Android API execution and physical device/Fold/Doze/battery/72-hour evidence. Update version, Readme, requirement status, report and this skill with verified outcomes; do not convert absent device evidence into release certification.
