# loftmobile-1126-02 · Hub, TOTP vault and transport refresh

The design uses the LOFT v3.6 guide and native UI specification. TOTP follows RFC 6238 and HOTP dynamic truncation. The local vault reuses SQLCipher and the Android Keystore wrapper. Explicit backup applies Argon2id and authenticated encryption before HTTPS. The Worker stores scoped encrypted bytes using D1 conditional writes. [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) · [RFC 4226](https://www.rfc-editor.org/rfc/rfc4226) · [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106) · [D1 API](https://developers.cloudflare.com/d1/worker-api/d1-database/)

The persistent Hub identity is separate from Portal's short user grant. The app keeps its Hub session across restarts and exposes explicit logout. Mail requires the current Portal user grant and can ask for fresh consent without signing out of Hub. The durable bearer uses independent revocation at Hub. Portal 2.2.x exposes no refresh grant or source account revocation event for this integration. [OAuth Security BCP](https://www.rfc-editor.org/rfc/rfc9700) · [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
