# LOFT native Android framework

Task `loftmobile-1126-02`, release profile `0.1.5-LYNX`, product `loft`, application ID `net.aptist.loft`. The delivery ABI is ARM64, minimum Android 10/API 29 and target/compile API 36. VersionName comes from the root VERSION file and versionCode is 6. The Account page opens explicit Portal browser authorization for a saved HTTPS Hub. The resulting account can reopen from the encrypted store, and a current read-only mail grant enables manual inbox and trash reads. Shield remains a framework boundary. Compilation and JVM evidence do not establish actual Android packet, handset or battery acceptance.

The Compose UI uses system fonts, bundled vectors and an icon-only module rail, with full accessible names in en/zh/ja/de and selected state retained on child pages. Node import, node details, routing drafts, server candidates, receipts and appearance preferences use the same native views. Complete imports must fit the 60 KiB command frame. Larger links need a bounded file adapter.

The private command worker restores one Rust-owned SQLCipher database under Android's `noBackupFilesDir`. A non-exportable Android Keystore AES-GCM wrapping key protects the 32-byte database secret. The worker publishes an authenticated provisioning envelope atomically before creating the database, and seals an active envelope before admitting writes. Existing ciphertext survives key loss or recovery failure. The UI displays a localized retry or recovery action. Clearing LOFT storage through Android settings is a separate deliberate action that also clears appearance preferences.

Node configurations, imported credentials, the server candidate and saved routing and network privacy settings survive binding and process restarts. Appearance preferences store theme and locale. Pending drafts, OS permission, active VPN state and temporary UI receipts remain process-local.

The node directory reads generation-bound pages of at most 50 rows at offsets 0/50/100/150 from the full 200-record workset. Previous/next/refresh use a separate bounded AIDL query and reject stale binding, request and generation callbacks. Leaving the page or unbinding cancels its UI request. A selected stable ID and bounded redacted metadata survive page changes; Rust's active node remains separate from this draft. Reading a page starts no Go, TUN or network work.

Import, account, mail and vault pages use FLAG_SECURE, with secure background/recents protection retained until page leave or Activity destruction. API29+ fully and partially obscured touch gestures are consumed. Obscuration after an accepted DOWN sends an unobscured CANCEL before consuming the remainder. API31+ overlay hiding and decor filtering follow the active sensitive page and clear on background/normal pages. The manifest declares HIDE_OVERLAY_WINDOWS. Android dispatch, genuine overlays, Compose controls, TalkBack and IME/focus behavior need their own device evidence.

A private `LoftCoreService` and a BIND_VPN_SERVICE-gated `LoftVpnService` share `LoftRuntimeOwner` in `:vpn`. The owner keeps exactly one generated UniFFI AppCore. Guest/account/mail display initializes no Go runtime, socket, DNS query or TUN. Explicit VPN work validates the generated engine's inert capabilities and actual Android gomaxprocs=2 before lazily constructing the current gomobile VPNRuntime. Rust owns connection state, opaque start tickets, exact routing and engine receipt admission; Kotlin owns Android resources, UI drafts and Binder. Go owns actual protocol forwarding and a duplicate TUN descriptor. Android retains the original descriptor.

AIDL bounds messages, checks caller UID and admits eight queued ordinary commands/four subscribers. All snapshot paths reserve/query/encode under one short publication lock. The independent unsigned publication sequence prevents late Connected frames from replacing equal-business-generation Stopping/Unavailable frames; exhaustion fails transport rather than recycling a sequence. The retained application-context client uses strict binding/visibility admission, reliable receipts and Binder-death invalidation. Stop has a separate cancellation/cleanup path and remains available during another UI command.

Hub I/O uses a separate one-request worker and the same Rust core lease. Android HTTPS accepts the platform CA trust and a URL from a Rust operation ticket, disallows redirects and bounds the response before passing it to Rust. The 60 KiB Hub result frame carries a validated account and one UI mail page or message preview. The Portal bearer remains on Hub, and the Hub session bearer and login proof stay in `:vpn`. A message uses native text with its original read state. Saving full text or an attachment opens Android's document picker and transfers the selected writable FD to the private service. Expiry of the source mail grant clears the mailbox presentation and preserves the signed-in account. The user can explicitly renew mail access in Account. Foreground or page exit cancels ordinary mail reads. Account startup, opening Mail and returning from the browser make no automatic Hub request.

The offline-first `totp` module stores authenticator entries and passwords in the same encrypted database. Users add an entry by manual key, setup URI or an explicit CameraX 1.5.3 scan with bundled ZXing Core 3.5.4. They can edit, archive or restore an entry. System device authentication gates a single selected reveal. An expired code or backgrounding clears its display. The paired SDK uses a device credential confirmation on API29 and BiometricPrompt with strong biometric or device-credential fallback on API30+. Encrypted backup sync takes an explicit recovery passphrase and runs on a single worker separate from VPN Stop. See the [vault contract](../docs/contracts/vault.md).

Connect uses the actual Android VPN permission workflow with a retained node/generation draft. Rust beginVpn returns an opaque ticket; only the private service consumes its single-use raw node. The actual Builder uses 198.18.0.1/30, MTU1280, IPv4 default route and synthetic DNS198.18.0.2. DNS is forwarded over selected-proxy TCP to the public resolver1.1.1.1:53, without direct fallback; it is not Gateway enterprise DNS. IPv6 is blocked inside the VPN scope by Android family policy and Go packet admission. Selected mode expands installed shared-UID peers, freezes exact packages and requires every Builder admission to succeed. Other UID groups remain direct.

Initial underlying-network selection belongs to Builder.setUnderlyingNetworks before establish. The service-level setter updates an already established VPN and returns false before one exists; API29 source and actual X/Pro pre-TUN failures established this distinction. The configured-VPN systemExempted eligibility path requires FOREGROUND_SERVICE_SYSTEM_EXEMPTED and the VPN app-op/user consent, independently of the alternative alarm-permission path. A service-scoped ForegroundServicePermission lint ignore documents lint31.13.2's missing VPN alternative; no alarm permission or global suppression is added.

Socket protection validates a real Internet socket descriptor with public Android APIs, binds to the captured physical Network and protects before use. Node bootstrap DNS uses that same Network with a fixed creation deadline of five seconds, CancellationSignal, bounded callback work and at most eight literal IPv4 answers. No direct fallback or hidden polling is used. Protected authentication, actual TUN readiness and exact applied packages are required before Rust accepts Connected.

After authentication/runtime/network failure with an established TUN, Android holds the original descriptor and foreground owner. Forwarding disable is claimed only after the Android Start joins and Go reports no pending ownership. Per-attempt failure admission issues Abort and the Rust failure mutation once; repeated teardown callbacks cannot create a generation/snapshot/page-query feedback loop. A later actual disable receipt may publish Blocked once, and a no-TUN failure can settle after construction joins. Stop/revoke fences Rust readiness, cancels DNS/Go outside the import queue, and closes the original independently of Rust availability. Disconnected requires confirmed Go/resource joins and descriptor closure; physical closure can be reported separately when the Rust state is unavailable. No timer or automatic retry manufactures recovery. Configured VPN apps use the systemExempted foreground type; real OS permission and startup evidence remain required.

Stop entry establishes/coalesces its admission guard, applies the atomic Rust cancellation fence and closes the captured original promptly. A delayed coalesced callback cannot close a replacement. Publication, native-resource monitor lookups/retains and bounded Go Abort/join execute on the reserved cleanup worker; Go Abort precedes the construction join. Caller return and original closure do not claim forwarding disable or Disconnected while the Go duplicate/workers remain owned. Resolver cancellation closes its query gate terminally, so a stale stopped precheck cannot create a later DNS query. Cancellation signals/latches are released on entry; callback-worker join belongs cleanup.

Layout uses actual inset-adjusted window dp constraints and WindowManager1.5.1 FoldingFeature information. Compact outer screens use one pane; readable medium/expanded regions use supporting/list-detail panes. Up to two vertical hinges are excluded, the rail relocates when necessary, and tabletop divides safe top/bottom regions. Font scale, landscape, split windows and refolding preserve drafts, selection and the retained service binding. Pixel Fold/Samsung Fold hardware acceptance remains pending.

From this directory, after generating a matching x86_64 native input root:

```bash
ANDROID_HOME=/home/coder/.local/share/loft-mobile/android-sdk \
python3 ../scripts/run_gradle.py -p . \
  -PloftTestAbi=x86_64 -PloftNativeGeneratedRoot=/absolute/path/generated \
  :app:testDebugUnitTest :ui-foundation:test \
  :app:assembleDebug :app:assembleDebugAndroidTest \
  --no-daemon --max-workers=1 -Dorg.gradle.jvmargs=-Xmx1536m \
  -Pkotlin.compiler.execution.strategy=in-process
```

The two test APKs are under app/build/test-x86_64/outputs/apk/debug and androidTest/debug. Running the default ARM64 build omits both test properties. A successful configuration check does not prove either test APK was built or executed.
